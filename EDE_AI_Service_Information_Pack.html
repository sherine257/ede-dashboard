أُعدّ هذا المستند لتزويد الهيئة بالمعلومات المطلوبة لدعم تنفيذ الخدمة الذكية لـتصريح استيراد الأدوية للاستخدام الشخصي، ويغطي: النماذج اللغوية الكبيرة، حجم الاستخدام والسعات، متطلبات Document AI، منصة الذكاء الاصطناعي المساعد (Agentic AI)، والمكوّنات التي تتطلب موارد حوسبة متخصصة.

This pack answers the authority’s request for LLM choices, expected usage/capacity, Document AI requirements, the agentic AI platform under consideration, and any components that need specialised compute.

الأرقام أدناه تقديرات تخطيطية لتصميم السعة، وليست أرقام تشغيل فعلية. يُفضَّل استبدالها بإحصاءات الهيئة (حركة المسافرين، طلبات التصاريح التاريخية، مواسم الذروة) قبل اعتماد الميزانية النهائية.

1) النماذج اللغوية الكبيرة (LLMs) قيد النظر

يُقترح نموذج تشغيلي سيادي / داخل المنطقة (دولة الإمارات أو منطقة سحابية معتمدة للجهات الحكومية)، مع فصل واضح بين نماذج المحادثة ونماذج الاستدلال على القواعد.

الاستخدامالنموذج المقترح (أساسي)بديل قيد التقييمالمبرر
مساعد المتقدم (محادثة عربية/إنجليزية + الأسئلة الشائعة) Azure OpenAI GPT-4.1 / GPT-4o
داخل Azure UAE / سيادي		 نماذج عربية مؤسسية: Jais / ALLaM / Fanar عبر مزود سيادي (G42 / Core42 / هيئة محلية) جودة ثنائية اللغة، التزام بالتعليمات، إمكانية الاستضافة الإقليمية
تصنيف الطلب (مقيم / مسافر) وشرح القواعد BR GPT-4.1 mini / GPT-4o mini للمسارات القصيرة نموذج استدلال أصغر مستضاف ذاتياً إن لزم عدم الخروج من الشبكة زمن استجابة منخفض وتكلفة أقل للمهام المحددة
توصية الضابط: موافقة / رفض / طلب استكمال GPT-4.1 مع استدعاء أدوات (function calling) على محرك القواعد نفس المنصة مع تقييد المخرجات JSON Schema القرار النهائي للضابط؛ النموذج يقترح فقط وفق القواعد والوثائق
توليد ملخص التدقيق وملاحظات التصريح GPT-4.1 mini — نصوص قصيرة منظمة

مبادئ اختيار النماذج

  • عدم تخزين بيانات الهوية أو الوصفات في تدريب النماذج.
  • تفضيل Azure OpenAI في منطقة الإمارات / اشتراك حكومي للتكامل مع منظومة مايكروسوفت القائمة لدى الهيئة (التقارير ولوحات المعلومات).
  • إبقاء محرك القواعد (Business Rules) خارج النموذج: BR-01، BR-02، BR-06، BR-07، BR-09، BR-11، BR-21 تُنفَّذ برمجياً، والنموذج يشرح النتيجة فقط.
  • دعم العربية والإنجليزية في واجهة المساعد.

LLMs under consideration: Primary conversational and officer-assist model: Azure OpenAI GPT-4.1 / GPT-4o in a UAE-sovereign or government-approved region. Smaller GPT-4.1 mini for classification and summaries. Arabic-specialised alternatives (Jais / ALLaM / Fanar) remain in evaluation for FAQ chat if a national model mandate applies. Business rules are executed in code; the LLM does not decide eligibility on its own.

خدمات Document AI المقترحة

  • Azure AI Document Intelligence (Read + Layout + نماذج مخصّصة للوصفة والتقرير الطبي + نموذج هوية).
  • طبقة تحقق لاحقة: تاريخ الوصفة ≤ 90 يوماً، التقرير ≤ 365 يوماً، وجود ختم/ترخيص، مطابقة الاسم مع UAE PASS.
  • مطابقة الدواء عبر سجل الهيئة (بحث الاسم والمادة الفعالة؛ إن لم يوجد: «No Record Found» ثم إدخال يدوي + مراجعة تنظيمية — BR-09).

Document AI: Emirates ID, passport, prescription (JPG/PNG/PDF only, not JPEG), medical report (within 1 year), optional supporting letters. Year-1 ~40k–90k pages, 25k–50k extraction jobs, 0.4–1.2 TB encrypted storage. Stack: Azure Document Intelligence (Read/Layout/custom) plus rule checks and EDE medicine registry matching. Applicant confirms extracted fields; officer sees source + extraction.

4) منصة الذكاء الاصطناعي المساعد (Agentic AI Platform)

المنصة قيد النظر هي منصة وكلاء متعددة الأدوات، وليست نموذجاً لغوياً وحده. الوكيل ينفّذ خطوات محددة مع بقاء الإنسان في الحلقة.

المكوّنالخيار الأساسيبديل
منصة الوكلاءAzure AI Foundry — Agent Service + Azure AI StudioMicrosoft Copilot Studio للمسارات البسيطة؛ LangGraph / Semantic Kernel للاستضافة الخاصة
تنسيق الأدواتSemantic Kernel أو Azure Functions كأدوات: قواعد BR، سجل الأدوية، UAE PASS (قراءة الملف الشخصي فقط)، Document Intelligenceنفس الأدوات عبر API Gateway داخلي
الوكلاء1) وكيل المتقدم (FAQ + توجيه الخطوة)
2) وكيل الوثائق (استخراج + اكتمال الملف)
3) وكيل الأهلية (تشغيل القواعد)
4) وكيل الضابط (توصية موافقة/رفض/استكمال)		دمج 3 و4 في وكيل واحد مع صلاحيات مختلفة
الذاكرة / المعرفةAzure AI Search (RAG) على الأسئلة الشائعة المعتمدة وسجل الأدوية — بدون تدريب على بيانات الأفرادقاعدة معرفية داخل الشبكة
الهوية والدخولUAE PASS للمتقدم · هوية مؤسسية (Entra ID) للضابط—
التدقيقسجل قرارات: المدخلات، القاعدة المشغّلة، توصية الذكاء الاصطناعي، قرار الضابط، الختم الزمنيSIEM / Microsoft Purview

ضوابط الوكيل (ملزمة)

  • لا موافقة تلقائية على الأدوية الخاضعة للرقابة (BR-21) أو الحقن (BR-11) أو غير المدرجة دون مستندات كاملة (BR-09).
  • التوصية للضابط: موافقة فقط إذا استُوفيت كل القواعد؛ طلب استكمال عند نقص المستند؛ رفض عند مخالفة الكمية/المدة.
  • المخرجات مقيّدة JSON؛ يُمنع تنفيذ دفع أو إصدار تصريح إلا عبر خدمة خلفية مصرّح بها.

Agentic platform: Azure AI Foundry Agent Service (primary), with Semantic Kernel / Azure Functions tools for business rules, medicine registry, UAE PASS profile read, and Document Intelligence. Four agents: applicant assistant, document agent, eligibility/rules agent, officer recommendation agent. Knowledge via Azure AI Search RAG on approved FAQs and the registry only. UAE PASS for applicants, Entra ID for officers. Full audit trail. No auto-approval of controlled, injectable, or unmatched products.

خلاصة البنية التحتية عند الإطلاق (بدون GPU محلي)

  • تطبيق ويب + واجهات برمجية (App Service / AKS) — حوسبة عامة.
  • قاعدة بيانات علائقية للطلبات + Blob للوثائق.
  • Azure OpenAI + Document Intelligence + AI Search في منطقة حكومية/إماراتية.
  • مراقبة: سجلات، تكلفة الرموز، زمن الاستخراج، نسبة توصيات الضابط المقبولة.

Specialised compute: Launch on managed Azure OpenAI + Document Intelligence — no on-prem GPU. GPU (A100/H100 class, HA pair) only if a sovereign Arabic model must be self-hosted. Vector search, PDF/QR generation, and app hosting are standard CPU. Optional later: image-integrity / vision models.
